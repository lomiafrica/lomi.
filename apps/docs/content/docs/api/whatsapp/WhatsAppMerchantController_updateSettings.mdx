## Overview

Sets `inbound_payment_link` to `off`, `keyword`, or `any`. Connect WhatsApp first.

## Authentication

Merchant routes require an API key in the `X-API-KEY` header (see [Integration overview](/api)). Use a **test** key against `https://sandbox.api.lomi.africa` and a **live** key against `https://api.lomi.africa`.

## Endpoint

`PATCH /whatsapp`

Base URLs:

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Request

### Path parameters

_No path parameters._

### Query parameters

_No query parameters._

### Body

| Name | Required | Schema | Description |
| --- | --- | --- | --- |
| `inbound_payment_link` | Yes | `off` \| `keyword` \| `any` | When an inbound text gets a payment link. |

## Responses

| Status | Description |
| --- | --- |
| `200` | Updated reply setting |
| `401` | Invalid or missing API key |

## Errors

Errors follow the standard JSON error format. **401** means the key is missing or invalid. **400** means `inbound_payment_link` is missing or not one of `off`, `keyword`, or `any`.

## Example

```bash
curl -sS -X PATCH "https://sandbox.api.lomi.africa/whatsapp" \
  -H "X-API-KEY: $LOMI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"inbound_payment_link":"keyword"}'
```
