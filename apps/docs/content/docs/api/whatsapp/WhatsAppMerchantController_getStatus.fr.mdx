## Aperçu

Indique si l'organisation a connecté WhatsApp, le numéro affiché, et `inbound_payment_link`.

`keyword` répond à un mot de paiement ou à un message qui n'est qu'un montant. `any` répond à chaque texte. `off` ne répond jamais tout seul. Le marchand garde la conversation dans l'application WhatsApp.

## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`GET /whatsapp`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Requête

### Paramètres d'URL

_Aucun paramètre d'URL._

### Paramètres de requête

_Aucun paramètre de requête._

### En-têtes

| Nom | Emplacement | Obligatoire | Schéma | Description |
| --- | --- | --- | --- | --- |
| `X-API-KEY` | header | Oui | string | Clé API marchande. |

## Réponses

| Statut | Description |
| --- | --- |
| `200` | Statut de connexion, numéro affiché, et `inbound_payment_link` |
| `401` | Clé API invalide ou manquante |

## Erreurs

Les erreurs suivent un format JSON standard. **401** : clé manquante ou invalide. **429** : trop de requêtes.

## Exemple

```bash
curl -sS -X GET "https://sandbox.api.lomi.africa/whatsapp" \
  -H "X-API-KEY: $LOMI_SECRET_KEY"
```
