## Aperçu

Créer un virement

Virement vers votre compte enregistré (self) ou vers un tiers sur mobile money (beneficiary).


### Quand l’utiliser

Utilisez pour les mouvements de trésorerie depuis votre solde lomi.

### À savoir

Les retraits self exigent payout_method_id ; les bénéficiaires Wave exigent recipient.name et recipient.phone (pas payout_method_id). Les rails Wave renvoient 400 avec une clé test, clés live uniquement. MTN renvoie 400 tant que non pris en charge.

### Voir aussi

[Lister les retraits](/api/payouts/PayoutsUnifiedController_findAll) · [Vérifier le solde disponible](/api/balances/AccountsController_checkAvailableBalance)


## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`POST /payouts`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Requête

### Paramètres d’URL

_Pas d’autre paramètre dans l’URL._


### Paramètres de requête

_Aucun paramètre de requête._


### Corps de la requête

_Pas de corps JSON pour cette opération._


## Réponses

| Statut | Description |
| --- | --- |
| `201` | Virement initié |
| `400` | Entrée invalide ou rail non pris en charge |

## Erreurs

Les erreurs suivent un format JSON standard. **401** : clé manquante ou invalide. **404** : ressource introuvable. **429** : trop de requêtes. Pour les créations, envoyez une clé d’idempotence si votre flux le permet.

## Exemple

```bash
curl -sS -X POST "https://sandbox.api.lomi.africa/payouts" \
  -H "X-API-KEY: $LOMI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```
