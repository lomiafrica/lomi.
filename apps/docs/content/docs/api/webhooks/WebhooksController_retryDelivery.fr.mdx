## Aperçu

Relancer une livraison webhook

### Quand l’utiliser

Utilisez cet endpoint quand vous devez exécuter `POST /webhooks/&#123;id&#125;/deliveries/&#123;deliveryId&#125;/retry` (Relancer une livraison webhook).



### Voir aussi

[Webhook delivery logs](/api/webhooks/WebhookDeliveryLogsController_findOne)

## Authentification

Les routes marchandes nécessitent une clé API dans l’en-tête `X-API-KEY` (voir [Vue d’ensemble](/api)). Utilisez une clé **test** avec `https://sandbox.api.lomi.africa` et une clé **live** avec `https://api.lomi.africa`.

## Endpoint

`POST /webhooks/{id}/deliveries/{deliveryId}/retry`

URLs de base :

- `https://sandbox.api.lomi.africa`
- `https://api.lomi.africa`

## Requête

### Paramètres d’URL

| Nom | Obligatoire | Schéma | Description |
| --- | --- | --- | --- |
| `deliveryId` | Oui | - | Delivery log UUID |
| `id` | Oui | - | Webhook UUID |

### Paramètres de requête

_Aucun paramètre de requête._


### Corps de la requête

_Pas de corps JSON pour cette opération._


## Réponses

| Statut | Description |
| --- | --- |
| `200` | - |

## Erreurs

Les erreurs suivent un format JSON standard. **401** : clé manquante ou invalide. **404** : ressource introuvable. **429** : trop de requêtes. Pour les créations, envoyez une clé d’idempotence si votre flux le permet.

## Exemple

```bash
curl -sS -X POST "https://sandbox.api.lomi.africa/webhooks/value/deliveries/value/retry" \
  -H "X-API-KEY: $LOMI_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```
