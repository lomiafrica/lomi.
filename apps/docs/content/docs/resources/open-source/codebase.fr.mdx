## Hébergé vs open source

**Les paiements en production passent uniquement par la plateforme hébergée de lomi.** Le monorepo est un espace de travail local pour l’équipe lomi. Chaque application peut aussi être déployée depuis son propre dépôt GitHub, mais l’arborescence de référence est sur [github.com/lomiafrica/lomi.](https://github.com/lomiafrica/lomi.).

Cloner le dépôt **ne permet pas** d’auto-héberger le traitement des paiements de façon supportée. Utilisez la [plateforme hébergée](https://lomi.africa/sign-up) pour le trafic réel.

## Feuille de route

Nous ouvrons progressivement le monorepo. **L’auto-hébergement du stack paiement complet est un objectif à long terme**, pas une offre supportée en production aujourd’hui. La trajectoire : publier plus de code → documenter les prérequis opérateur (prestataires, MoR, conformité) → proposer une option auto-hébergée supportée quand le stack sera complet et sûr sans les services hébergés de lomi.

Ce qui est ouvert aujourd’hui :

- **Déjà en open source** :
  - Site de documentation : **`apps/docs`** (ce site)
  - CLI (**`apps/cli`**), outil d’intégration ; s’appuyer sur l’API hébergée, pas sur l’exploitation plateforme
  - Service API : **`apps/api`**
  - SDK : **`apps/sdks`**
  - Plugins e-commerce : dépôts séparés — [woo](https://github.com/lomiafrica/woo), [magento](https://github.com/lomiafrica/magento), [prestashop](https://github.com/lomiafrica/prestashop)
  - Serveur MCP (**`apps/mcp`**), outil d’intégration ; API marchande dans l’IDE, pas l’exploitation plateforme
  - Boilerplate événements (dépôt séparé) : **[lomiafrica/events](https://github.com/lomiafrica/events/)**

- **Bientôt** :
  - Tableau de bord marchand : **`apps/dashboard`**
  - Extension Shopify : **`apps/shopify`** (à publication)

- **Propriétaire** :
  - Tableau de bord admin : **`apps/admin`**

- **Produit hébergé (code pas entièrement public)** :
  - Checkout : **`apps/checkout`**
  - Storefront : **`apps/storefront`**
  - Portail client : **`apps/customers`**
  - Site marketing : **`apps/website`**

De nombreux fichiers, surtout les migrations et la logique paiement cœur, portent la mention `/* @proprietary license */` même dans des apps sous AGPL.

## Organisation du monorepo

```text filename="Structure du projet"
└── lomi./
    ├── README.md
    ├── CONTRIBUTING.md
    ├── LICENSE
    └── apps/
        ├── admin/        # Admin interne (propriétaire)
        ├── api/          # API paiement NestJS (open source)
        ├── checkout/     # Checkout hébergé (produit hébergé)
        ├── cli/          # CLI Rust (outil intégrateur ; open source)
        ├── customers/    # Portail client (produit hébergé)
        ├── dashboard/    # Tableau de bord marchand (ouverture prochaine)
        ├── design/       # Assets design partagés
        ├── docs/         # Documentation développeur (open source, cette app)
        ├── jumbo/        # Application marchande MPOS (terminal mobile)
        ├── mcp/          # Serveur MCP (outil intégrateur ; open source)
        ├── plugins/      # WooCommerce, Magento, PrestaShop, références
        ├── sdks/         # SDK TypeScript, Python, PHP, Go (open source)
        ├── storefront/   # Storefront marchand (produit hébergé)
        └── website/      # Site marketing (produit hébergé)
```

## Tableau de bord marchand (`apps/dashboard`)

Le tableau de bord est le back-office marchand (transactions, liens de paiement, paramètres, analytics). C’est un **produit hébergé** aujourd’hui ; le code s’ouvre progressivement.

Structure simplifiée :

```text filename="Tableau de bord (apps/dashboard)"
└── apps/dashboard/
    ├── package.json
    ├── .env.example
    ├── src/              # Application React (Vite)
    ├── supabase/         # Migrations DB et edge functions (référence)
    │   └── migrations/
    └── public/           # Assets statiques
```

Les migrations sous `supabase/migrations/` font foi pour le schéma plateforme. Ce n’est pas une recette pour exploiter votre propre stack paiement sans les services hébergés de lomi. et les accords prestataires.

## Contribuer

Les contributions sur les zones open source et la documentation sont les bienvenues. Ouvrez une issue ou une pull request sur le [monorepo lomi.](https://github.com/lomiafrica/lomi.).

Avant de contribuer :

1. Lisez notre [code de conduite](https://github.com/lomiafrica/lomi.?tab=coc-ov-file)
2. Consultez la [politique de sécurité](https://github.com/lomiafrica/lomi.?tab=security-ov-file)
3. N’altérez pas les fichiers marqués `/* @proprietary license */`

Voir [Contribuer](/resources/contributing/overview) et [CONTRIBUTING.md](https://github.com/lomiafrica/lomi./blob/master/CONTRIBUTING.md) du monorepo.
